Executive Summary

Heterogeneous datasets are difficult to use safely when quality, ownership, provenance and suitability are disconnected. Ingest and profile data through a shared pipeline that publishes normalized results, quality findings, lineage and explainable visualization recommendations.

Business Context

Analysts and platform teams need to know whether data is appropriate for a task, not merely whether a file loaded. The repository includes a real attributed weather sample and explicitly synthetic mobility/quality fixtures. Its cloud infrastructure definition is distinct from local processing and static visualization.

Technical Architecture

Engineering Challenges

Parsing multiple formats introduces resource and path risks. Dataset semantics can be uncertain; a recommendation should preserve source evidence and warnings. Large external raster/OSM inputs and cloud execution have dependencies beyond the included local fixtures.

Architecture Decisions

The shared normalized-result contract separates analysis from presentation, allowing the portal to consume pipeline outputs rather than disconnected numbers. The versioned registry makes onboarding explicit. Terraform and Kubernetes describe the cloud path; they do not prove a successful cloud apply. A simpler single-format pipeline could cost less where multimodal extensibility is unnecessary.

Implementation

Verdatrace modules implement ingestion, registry validation, quality, cataloging, analytics, evaluation, lineage and visualization decisions. scripts/build_demo.py builds frontend/data/platform_demo.json. main.tf, deployment.yaml and data_pipeline.py define the Pub/Sub worker and GCP resources. Some candidate datasets are disabled retrieval plans, not committed operational datasets.

Reliability and Security

Code and configuration include allowed path roots, allowlisted HTTPS retrieval, role checks, redaction, scoped IAM, workload identity and raw-storage public-access prevention. These controls require deployment validation. Optional raster workers and external data packs remain separate execution boundaries.

Business Value

Expected value: make quality and provenance visible before analytics consumes data and reduce repeated dataset assessment work. The case study claims no cloud cost savings, quality uplift percentage or production throughput. Local fixture tests are correctness evidence only.
