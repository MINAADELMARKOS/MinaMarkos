Executive Summary

Keep changing employee attributes available for historical reporting rather than overwriting prior values. An hourly DAG extracts HR/finance data to S3, identifies changes and branches into Snowflake dimension updates and inserts.

Business Context

Historical dimensions help analysts interpret a result using the attributes that applied at the relevant time. The repository demonstrates the orchestration pattern with named external connections.

Technical Architecture

Engineering Challenges

SCD Type 2 requires consistent effective dates, unique current rows and safe reruns. Branching reduces empty-operation failures but does not establish transactional correctness under retries. Provider versions and credentials are external prerequisites.

Architecture Decisions

The code uses Airflow tasks to make extraction, change detection and load dependencies explicit, with S3 as a staging boundary. For a smaller workflow, a database-native scheduled job might be simpler. The repository does not record an evaluated alternatives study.

Implementation

Dags/ETL_DAG.py uses PostgreSQL/S3 connection IDs, a Python change-detection helper and Snowflake operators. Includes contains SQL and transformation functions. Output screenshots are present. README retains template setup instructions and upstream image attribution; present as a learning project, not sole invention of the pattern.

Reliability and Security

Connection configuration, secrets, retry-safe writes and least-privilege data access must be validated against real services. No live PostgreSQL/S3/Snowflake test was executed here.

Business Value

Expected value: consistent historical reporting and inspectable workflow dependencies. No reduction in processing time or operational cost is claimed.
